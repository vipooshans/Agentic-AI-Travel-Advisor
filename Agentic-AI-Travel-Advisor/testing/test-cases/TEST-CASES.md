# Test-case catalogue

This catalogue maps the project's requirements to the automated tests that check them. Every case runs against the real system: the ASP.NET Core API, PostgreSQL, the React app and the Flutter app. Nothing here was executed by hand.

## How to read it

Each row has the following columns:
- **Test ID** and **Feature**.
- **Preconditions** and **Test Steps** describe what the automated test sets up and does.
- **Input** is the data sent.
- **Expected Result** is what the test asserts.
- **Actual Result** is what the recorded run produced.
- **Status** is `Pass`, `Fail` or `Not executed`.
- **Evidence** is one or more references written as `file` :: `test name`. The file is relative to `testing/execution-results/`, and the test name is the name (or a unique part of it) that appears in that file.

Check every reference with:

```powershell
powershell -ExecutionPolicy Bypass -File testing/scripts/verify-test-cases.ps1
```

The script fails if a referenced file or test is missing, or if a test's recorded outcome differs from the Status column:
- **TRX:** the outcome must be `Passed` for `Pass` and `NotExecuted` for `Not executed`.
- **JUnit:** there must be no failure, error or skip.
- **Flutter JSON report (`.jsonl`):** the test's result must be `success`.
- **Logs:** there must be no failure marker on the matching line.
